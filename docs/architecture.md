# بنية Conta الإنتاجية

## الهدف

نظام ويب يعمل على خادم خاص مع MongoDB Atlas، ثم يمكن لاحقًا إعادة استخدام واجهته وقواعد عمله في نسخة سطح مكتب محلية.

## شكل التطبيق

يُبنى النظام كـ **Modular Monolith** بدل خدمات صغيرة متعددة:

1. واجهة عربية لنقطة البيع والإدارة.
2. API واحد يحتوي وحدات المنتجات والمخزون والمبيعات والزبائن والتقارير.
3. MongoDB Atlas كمصدر الحقيقة.
4. عامل خلفي صغير للنسخ الاحتياطية والتقارير الثقيلة عند الحاجة.

هذا الشكل يبقى بسيطًا في التشغيل، مع فصل قواعد العمل عن واجهة المستخدم وعن طبقة MongoDB حتى يمكن إضافة مخزن محلي لاحقًا.

## المواقع الثابتة

| المعرّف | الاسم | الاستخدام |
|---|---|---|
| `warehouse` | المخزن الرئيسي | الحاويات وشحنات الموردين |
| `boutique` | البوتيك | البيع والاستلام المباشر من السوق |

## المجموعات الأساسية في MongoDB

| المجموعة | الغرض |
|---|---|
| `products` | المنتج، الباركود، حجم الكرتون، التكلفة والأسعار |
| `stockBalances` | رصيد كل منتج في كل موقع بوحدة الفرد |
| `stockMovements` | سجل غير قابل للحذف لكل دخول أو خروج أو تحويل |
| `suppliers` | الموردون والأشخاص الذين يتم الشراء منهم في السوق |
| `supplierLedger` | الاستلام على الحساب، الدفع للمورد، والمقاصة |
| `goodsReceipts` | سندات الاستلام ووجهتها المختارة |
| `transfers` | التحويل من المخزن إلى البوتيك |
| `sales` | رأس الفاتورة وبنودها والأسعار وقت البيع |
| `payments` | النقد وبنكيلي ومصرفي والسداد وبيم بنك |
| `customers` | الزبائن المسموح بتسجيل الملاحظات عليهم |
| `customerLedger` | الملاحظات والسداد والتصحيح |
| `users` | حساب المالك وتسجيل الدخول |
| `auditEvents` | من نفّذ العملية ووقتها وجهازها |
| `counters` | تسلسل أرقام الفواتير والسندات |

## تمثيل الكمية والسعر

- المخزون يُحفظ كعدد صحيح `quantityPieces`؛ لا يُحفظ رصيد كرتون منفصل.
- العرض يحسب `cartons = floor(quantityPieces / piecesPerCarton)` والباقي أفراد.
- البيع بـ 20 فردًا لمنتج حجمه 20 يتحول إلى كرتون واحد ويستخدم سعر الكرتون.
- إذا شملت الكمية كرتونًا وأفرادًا إضافية، يُحسب سعر الفرد الإضافي بنسبة `cartonPrice / piecesPerCarton`.
- سعر البيع المحفوظ افتراضي فقط؛ تحفظ الفاتورة السعر الفعلي الذي أدخله البائع لكل بند.
- الأموال تحفظ بصيغة MongoDB `Decimal128` باسم MRU ولا تُستخدم أرقام الفاصلة العائمة.

## العمليات الذرّية

كل عملية مهمة تنفذ داخل MongoDB Transaction واحدة.

### البيع

1. التحقق من مفتاح منع التكرار `idempotencyKey`.
2. قراءة أسعار المنتج المحفوظة في قاعدة البيانات، لا أسعار المتصفح.
3. التأكد من توفر الكمية في البوتيك.
4. خصم المخزون بشرط ألا يصبح سالبًا.
5. إنشاء الفاتورة وحركات المخزون.
6. إنشاء دفعة فورية، أو إضافة ملاحظة للزبون.
7. اعتماد جميع التغييرات معًا أو إلغاؤها جميعًا.

### الاستلام

1. يحدد المالك `warehouse` أو `boutique`.
2. يختار موردًا مسجلًا وطريقة التسوية: مدفوع أو على الحساب.
3. ينشأ سند استلام وحركة مخزون.
4. يزيد رصيد الموقع المختار فقط.
5. عند الاستلام على الحساب، ينشأ قيد مستحق للمورد بالقيمة الفعلية.

### المقاصة مع المورد

1. يجوز ربط الطرف نفسه بسجل مورد وسجل زبون.
2. قيمة المقاصة لا تتجاوز أصغر الرصيدين.
3. ينخفض المستحق للمورد ورصيد الزبون بالمبلغ نفسه داخل معاملة واحدة.
4. ينشأ قيد مستقل قابل للتتبع، ولا تُعدل القيود القديمة.

### التحويل

1. خصم الكمية من المخزن بشرط توفرها.
2. إضافتها إلى البوتيك.
3. إنشاء حركة واحدة تربط الموقعين.
4. لا ينشأ دخل أو ربح أو دفعة مالية.

### سداد الزبون

1. لا يتجاوز المبلغ الرصيد الحالي.
2. ينشأ قيد سداد في `customerLedger` ودفعة بالطريقة المختارة.
3. يحدث رصيد الزبون في المعاملة نفسها.

## ثوابت حماية البيانات

- فهرس فريد للباركود غير الفارغ ورمز المنتج.
- فهرس فريد لـ `productId + locationId` في الأرصدة.
- فهرس فريد لمفتاح منع تكرار كل عملية مالية.
- منع أي API من استقبال إجمالي الفاتورة كقيمة موثوقة من الواجهة؛ الخادم يعيد حسابه.
- لا حذف لفاتورة أو حركة مخزون بعد اعتمادها؛ التصحيح يكون بعكس العملية.
- جميع القيم القادمة من الواجهة تُفحص قبل دخولها إلى قاعدة البيانات.
- بيانات الدخول لا تظهر في السجلات، ولا تُرسل MongoDB مباشرة إلى المتصفح.

## النسخ الاحتياطي

- تفعيل Atlas Cloud Backup للبيئة الإنتاجية.
- لقطة يومية واحتفاظ أسبوعي وشهري مناسب لحجم المتجر.
- تصدير دوري مشفر خارج حساب الخادم.
- اختبار استعادة حقيقي بصورة دورية، لا الاكتفاء بوجود لقطة.

## طريق نسخة سطح المكتب

واجهة المستخدم وقواعد الكرتون والحسابات تبقى مشتركة. تُضاف طبقة تخزين محلية منفصلة باستخدام SQLite، مع أداة ترحيل واضحة من Atlas. المزامنة بين جهاز محلي والخادم ليست مجرد تغيير اتصال؛ إن طُلبت ستنفذ بطابور عمليات ومفاتيح منع التكرار وحل تعارضات صريح.
